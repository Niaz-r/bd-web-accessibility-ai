2.4.4 Link Purpose (In Context) — Level A

Why this matters

A link without a meaningful accessible name may give screen-reader users little or no information about the link's purpose or destination.

Recommendation

Provide a meaningful accessible name for the link. Prefer descriptive visible link text. When visible text is not appropriate, use a supported accessible naming mechanism and verify it with assistive technology.

Manual review: Yes
Verify the computed accessible name in the rendered page because JavaScript, ARIA, or nested content may affect the final accessible name.

Example

Before 
<a href="/admission"></a>
After 
<a href="/admission">Undergraduate admission information</a>
Alternative/context-dependent fix 
For an icon-only link, provide an appropriate accessible name and test the rendered result.

WCAG relationship

2.4.4 Link Purpose (In Context) — Level A

Why this matters

Generic text such as 'Read More', 'Click Here', or 'Learn More' may be difficult to understand when links are encountered outside their visual context.

Recommendation

Prefer link text that communicates the purpose or destination. If short generic text is retained, verify that its purpose can be determined from programmatically associated context.

Manual review: Yes
WCAG allows link purpose to be determined from the link text together with programmatically determined context. Therefore generic wording alone is not sufficient evidence of failure.

Example

Before 
<a href="/admission">Read More</a>
After 
<a href="/admission">Read more about undergraduate admission</a>
Alternative/context-dependent fix 
Retain concise wording only when sufficient programmatically determined context clearly identifies the link purpose.

1.1.1 Non-text Content — Level A

Why this matters

Images without an appropriate text alternative may not communicate their purpose or information to users of screen readers and other assistive technologies.

Recommendation

Determine whether the image is informative, functional, or decorative. Informative images should receive concise alternative text that communicates their purpose. Decorative images should normally use an empty alt attribute so assistive technology can ignore them.

Manual review: Yes
The scanner cannot reliably determine the purpose of the image from static HTML alone. Also verify whether another supported accessible-name mechanism already provides an equivalent alternative.

Example

Before 
<img src="campus.jpg">
After 
<img src="campus.jpg" alt="Students entering the university library">
Alternative/context-dependent fix 
<img src="decoration.png" alt="">

2.4.6 Headings and Labels — Level AA

Why this matters

An empty heading can create an unhelpful navigation stop for users who navigate pages by headings and does not describe a topic or purpose.

Recommendation

Remove the heading element if no heading is required, or provide concise meaningful heading text describing the associated section.

Manual review: Yes
Confirm the rendered heading content and whether CSS, JavaScript, or assistive naming affects what users actually encounter.

Example

Before 
<h2></h2>
After 
<h2>Admission Requirements</h2>
Alternative/context-dependent fix 
Remove the empty heading if it has no semantic purpose.

WCAG relationship

1.3.1 Info and Relationships — Level A

Why this matters

Unexpected heading-level jumps can make the relationship between page sections harder to understand for users navigating by headings.

Recommendation

Review the logical hierarchy of the page. Nest headings according to section relationships and avoid skipping levels when the skipped level would represent a missing structural relationship.

Manual review: Yes
A numerical heading-level jump is not always a WCAG failure. For example, moving back from an h4 to an h2 can correctly close subsections. Human review of the document outline is required.

Example

Before 
<h2>Programs</h2><h4>Computer Science</h4>
After 
<h2>Programs</h2><h3>Computer Science</h3>
Alternative/context-dependent fix 
Choose heading levels according to semantic hierarchy, not visual appearance.

WCAG relationship

1.3.1 / 2.4.6 — Level A / AA

Why this matters

A clear page-level heading can help users understand the topic of the page and navigate its structure, particularly when using assistive technology.

Recommendation

Review the page structure and provide a meaningful top-level heading when appropriate. The heading should describe the page's primary content or purpose.

Manual review: Yes
WCAG does not simply require exactly one h1 on every page. The complete heading structure and content organization must be evaluated.

Example

Before 
<main><p>Admission information...</p></main>
After 
<main><h1>Undergraduate Admission</h1><p>Admission information...</p></main>
Alternative/context-dependent fix 
Use heading levels according to the logical document structure rather than visual size alone.
